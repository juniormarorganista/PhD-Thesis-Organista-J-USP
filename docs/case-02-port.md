# MMS Case 02 - Python port

This document records the port of the original Fortran file:

```text
src/fortran_original/4Order_LPOG_Euler/case_02.f
```

Case 02 is the second of the 13 MMS cases ported after Case 12 (Etapa 14).
Its velocity, vorticity and stream-function fields (`u`, `v`, `wz`, `psi`)
are algebraically identical to Case 01. The polymeric stress field is a
quadratic polynomial in `x` and `y`
(`Axx = a1xx + a2xx x + a3xx x^2`, `Bxx = b1xx + b2xx y + b3xx y^2`, and
analogously for `xy`/`yy`), reusing
`mms_viscoelastic.manufactured_solutions.case_12.Case12Coefficients` since
the field names and `par.nn` defaults (all equal to one) match exactly.

## Ported components

```text
exact_solutions_case_02(t)   -> manufactured_solutions/case_02.py
source_term_case_02(t)       -> source_terms/case_02.py
boundaries_condictions_case_02(t)  -> not ported separately (see Case 01)
```

## Relaxation-term simplification

Each tensor source term contains a sub-expression of the form

```text
a1xx*Bxx + a1yy*Byy
+ x*(a2yy*b1yy + a2yy*y*(b2yy + b3yy*y)
     + a2xx*Bxx + a3xx*x*Bxx + a3yy*x*Byy)
```

which is algebraically identical to `Axx*Bxx + Ayy*Byy` (the same
structure used by Case 12's relaxation term). This was verified with
SymPy (the difference expands to exactly `0`) before using the simplified
form in the Python port.

## Transcription method and a caught error

Rather than retyping each dense algebraic expression by hand, the four
source terms in the standalone Fortran reference
(`validation/fortran_reference/case02_fields/case02_fields_reference.f90`)
were generated by a small script that mechanically strips the Fortran77
continuation prefix and swaps `dexp` for `exp`, preserving every
parenthesis of the original. The first hand-written Python transcription
of `tfTyy` was missing a `Wi *` multiplication, and the first hand-written
Fortran reference for `tfTxy` had one extra closing parenthesis; both were
caught before merging, the first by comparing against the structure of the
other two tensor components, the second by the mechanical re-extraction's
parenthesis-balance check.

## Python API

```python
from mms_viscoelastic.grids import Grid2D
from mms_viscoelastic.manufactured_solutions import Case02Parameters, evaluate_case_02_exact
from mms_viscoelastic.source_terms import Case02SourceTermParameters, evaluate_case_02_source_terms

grid = Grid2D.from_bounds(nx=33, ny=33)
field = evaluate_case_02_exact(grid, t=0.0, parameters=Case02Parameters())
terms = evaluate_case_02_source_terms(grid, t=0.0, parameters=Case02SourceTermParameters())
```

## Validation status

- All eleven exported quantities validated against an independent
  standalone Fortran reference program
  (`validation/fortran_reference/case02_fields/`), at two grid sizes
  (`5x5`, `9x9`), to `max_abs_error < 1e-10` (observed: machine precision).
- Regression tests: `tests/test_case_02_manufactured.py` (shapes, known
  values, identity of `u`/`v`/`wz`/`psi` with Case 01, ML feature table)
  and `tests/test_case02_fields_fortran_reference.py` (Fortran cross-check).
- Example: `python examples/17_case02_fields_and_source_terms.py`.
