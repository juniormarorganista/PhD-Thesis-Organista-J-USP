# MMS Case 08 - Python port

This document records the port of the original Fortran file:

```text
src/fortran_original/4Order_LPOG_Euler/case_08.f
```

Case 08 is the eighth of the 13 MMS cases ported after Case 12 (Etapa
14), and one of the two largest and densest (678 lines, second only to
Case 09). Like Case 07, its velocity, vorticity and stream-function
fields decay in time through a hyperbolic tangent
(`1 - tanh(4 - 8*at*t)`), but with a purely polynomial spatial structure.
The polymeric stress field is a quadratic polynomial in `x` and `y`, the
same ansatz as Case 02, reusing
`mms_viscoelastic.manufactured_solutions.case_12.Case12Coefficients`.

The `u`/`v`/`wz`/`psi` formulas were verified self-consistent via the
stream-function identities (`u = dpsi/dy`, `v = -dpsi/dx`,
`wz = Laplacian(psi)`, the same sign convention as every other case) by
hand before the Fortran cross-validation ran.

## Ported components

```text
exact_solutions_case_08(t)   -> manufactured_solutions/case_08.py
source_term_case_08(t)       -> source_terms/case_08.py
boundaries_condictions_case_08(t)  -> not ported separately (see Case 01)
```

## Scale and transcription method

Case 08's manufactured solution makes the nonlinear convective Jacobian
(products of the velocity/vorticity fields with their own derivatives)
explicit in the source terms, rather than letting it vanish as in the
simpler trigonometric/polynomial cases. This makes every expression
substantially larger than Cases 01-07: `tfwz` has 14 top-level additive
terms (143 matched parenthesis pairs), and `tfTxx`/`tfTxy`/`tfTyy` each
have 156, 212 and 153 matched parenthesis pairs respectively -- `tfTxy`
is the densest single expression ported so far.

Given this scale, no part of either the Fortran reference or the Python
module was retyped by hand. Both were assembled entirely from the
output of the two mechanical scripts (Fortran-to-Fortran and
Fortran-to-Python): the Python module was generated by a small
assembly script that builds each function from the mechanically-split
top-level terms, then the whole file was passed through `ruff format`
to normalize whitespace and line-wrapping (a transformation that only
ever touches formatting, never semantics). The Fortran reference was
assembled the same way as Cases 02-07, substituting the mechanically
extracted expressions into the per-function template.

## Python API

```python
from mms_viscoelastic.grids import Grid2D
from mms_viscoelastic.manufactured_solutions import Case08Parameters, evaluate_case_08_exact
from mms_viscoelastic.source_terms import Case08SourceTermParameters, evaluate_case_08_source_terms

grid = Grid2D.from_bounds(nx=33, ny=33)
field = evaluate_case_08_exact(grid, t=0.0, parameters=Case08Parameters())
terms = evaluate_case_08_source_terms(grid, t=0.0, parameters=Case08SourceTermParameters())
```

## Validation status

- All eleven exported quantities validated against an independent
  standalone Fortran reference program
  (`validation/fortran_reference/case08_fields/`), at two grid sizes
  (`5x5`, `9x9`), to `max_abs_error < 1e-10` (observed: machine
  precision on the first attempt, despite the case's size and density).
- Regression tests: `tests/test_case_08_manufactured.py` (shapes, known
  values, ML feature table) and
  `tests/test_case08_fields_fortran_reference.py` (Fortran cross-check).
- Example: `python examples/23_case08_fields_and_source_terms.py`.

## Reproducing

```powershell
gfortran -O2 -std=f2008 `
  validation\fortran_reference\case08_fields\case08_fields_reference.f90 `

.\validation\fortran_reference\case08_fields\case08_fields_reference.exe `
  validation\reference_data\case08_fields_9x9_default.csv 9 9

python examples\23_case08_fields_and_source_terms.py
python -m pytest tests\test_case_08_manufactured.py tests\test_case08_fields_fortran_reference.py -v
```
