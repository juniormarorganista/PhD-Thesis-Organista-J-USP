# MMS Case 09 - Python port

This document records the port of the original Fortran file:

```text
src/fortran_original/4Order_LPOG_Euler/case_09.f
```

Case 09 is the ninth of the 13 MMS cases ported after Case 12 (Etapa 14),
and the largest and densest in the entire project (790 lines). Its
velocity, vorticity and stream-function fields (`u`, `v`, `wz`, `psi`)
are algebraically identical to Case 08 (verified: same formulas, also
cross-checked numerically in `tests/test_case_09_manufactured.py`). The
polymeric stress field uses the same trigonometric ansatz as Case
03/06/12, reusing
`mms_viscoelastic.manufactured_solutions.case_12.Case12Coefficients`.

## Ported components

```text
exact_solutions_case_09(t)   -> manufactured_solutions/case_09.py
source_term_case_09(t)       -> source_terms/case_09.py
boundaries_condictions_case_09(t)  -> not ported separately (see Case 01)
```

## The densest expression in the project

Case 09 combines Case 08's explicit nonlinear convective Jacobian
(products of the velocity/vorticity fields with their own derivatives,
which appear in the source terms rather than vanishing) with Case 06's
trigonometric stress ansatz. The combination makes `tfTxy` the densest
single expression ported in the whole project: 296 matched parenthesis
pairs (compared to 212 for Case 08's `tfTxy`, the previous record).
`tfwz` has 14 top-level additive terms (163 matched parenthesis pairs);
`tfTxx` and `tfTyy` have 220 and 213 respectively.

Given this scale, the same discipline established for Case 08 was
followed without exception: no part of either the Fortran reference or
the Python module was retyped by hand. Both were assembled entirely
from the output of the two mechanical scripts. The Python module was
generated by an assembly script that builds each function from the
mechanically-split top-level terms, then passed through `ruff format`
to normalize whitespace (a transformation that only ever touches
formatting, never semantics). The Fortran reference was assembled the
same way as every prior case, substituting the mechanically extracted
expressions into the per-function template.

## Python API

```python
from mms_viscoelastic.grids import Grid2D
from mms_viscoelastic.manufactured_solutions import Case09Parameters, evaluate_case_09_exact
from mms_viscoelastic.source_terms import Case09SourceTermParameters, evaluate_case_09_source_terms

grid = Grid2D.from_bounds(nx=33, ny=33)
field = evaluate_case_09_exact(grid, t=0.0, parameters=Case09Parameters())
terms = evaluate_case_09_source_terms(grid, t=0.0, parameters=Case09SourceTermParameters())
```

## Validation status

- All eleven exported quantities validated against an independent
  standalone Fortran reference program
  (`validation/fortran_reference/case09_fields/`), at two grid sizes
  (`5x5`, `9x9`), to `max_abs_error < 1e-10` (observed: machine
  precision on the first attempt, despite the unprecedented scale).
- Regression tests: `tests/test_case_09_manufactured.py` (shapes, known
  values, identity of `u`/`v`/`wz`/`psi` with Case 08, ML feature table)
  and `tests/test_case09_fields_fortran_reference.py` (Fortran cross-check).
- Example: `python examples/24_case09_fields_and_source_terms.py`.
