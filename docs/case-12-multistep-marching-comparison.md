# MMS Case 12 - Multi-step time marching

This document describes the multi-step time marching implemented in
[`src/mms_viscoelastic/numerics/time_marching.py`](../src/mms_viscoelastic/numerics/time_marching.py)
(`case12_multistep_march`), exercised by
[`examples/15_case12_multistep_comparison.py`](../examples/15_case12_multistep_comparison.py)
and tested in
[`tests/test_case12_multistep_march.py`](../tests/test_case12_multistep_march.py).

This is **Etapa 11** of the post-FASE-VII replanning
(`docs/planejamento-tecnico.md`, FASE VIII). It builds on the single
time-marching step from Etapa 10
([`docs/case-12-time-marching-comparison.md`](case-12-time-marching-comparison.md))
by chaining repeated calls to `case12_time_step` into a multi-step march.

> **Etapa 17 update.** `case12_time_step` (and therefore every step of this
> march) now uses the real 4th-order LPOG compact + Lele filter + multigrid
> Poisson pipeline instead of the 2nd-order placeholder. The Fortran
> reference program and its CSV were rewritten/regenerated to match. See
> [`docs/case-12-4th-order-time-marching.md`](case-12-4th-order-time-marching.md).

## 1. `case12_multistep_march`

`case12_multistep_march(state, t0, n_steps, grid, ...)` repeatedly applies
`case12_time_step` (Etapa 10), advancing the physical time by
`step_parameters.dt` at each iteration:

```python
current = state
for n in range(n_steps):
    current = case12_time_step(
        current,
        t0 + n * step_params.dt,
        grid,
        step_parameters=step_params,
        field_parameters=field_parameters,
        source_parameters=source_parameters,
    )
return current
```

Each iteration performs the full Etapa 10 sequence: evaluate the manufactured
source terms at the current time, advance `wz`, `Txx`, `Txy`, `Tyy` by one
explicit Euler step, re-impose Dirichlet boundary conditions at `t + dt`,
re-solve the Poisson equation for `psi`, and recompute `u`/`v` from the
updated `psi`. The boundary conditions and source terms are re-evaluated at
the correct physical time `t0 + n * dt` at every step -- there is no special
casing for `n_steps` or for the manufactured-solution parameters.

## 2. Time-independence at `at = 0`

`Case12Parameters.at` and `Case12SourceTermParameters.at` default to `0.0`.
With `at = 0`, `evaluate_case_12_exact` computes `decay = exp(at * t) == 1`
for all `t`, and `evaluate_case_12_source_terms` computes `exp_at =
exp(at * t) == 1` and several `at * (...)` terms that vanish. Consequently,
with the default parameters, **both the exact boundary fields and the
manufactured source terms are identical at every time step** -- the Case 12
`ty_sim == 1` formulation used throughout this project is, by construction, a
steady-state manufactured solution.

This is purely a property of the *inputs* re-evaluated at each step; the
Python implementation in Section 1 still calls `evaluate_case_12_exact` and
`evaluate_case_12_source_terms` at the correct `t` on every iteration (a
no-op for `at = 0`, but correct for any `at`). The Fortran reference program
(Section 3) exploits this property as an implementation shortcut: it reuses
the `t = 0` input CSV (boundary values and source-term columns) at every
iteration instead of regenerating per-step CSVs, which would otherwise be
required for a general `at != 0` reference.

## 3. Fortran reference program

[`validation/fortran_reference/case12_multistep/case12_multistep_reference.f90`](../validation/fortran_reference/case12_multistep/case12_multistep_reference.f90)
is a standalone program (it does not modify or depend on the original thesis
Fortran files) that:

1. Reads the same input CSV as Etapa 10
   (`x,y,u,v,wz,psi,txx,txy,tyy,tfwz,tftxx,tftxy,tftyy`, generated by
   [`generate_input_csv.py`](../validation/fortran_reference/case12_time_step/generate_input_csv.py)
   from `evaluate_case_12_exact` and `evaluate_case_12_source_terms` at `t=0`
   on a `9 x 9` grid).
2. Evaluates the exact manufactured fields once at `t = dt` (constant across
   steps, per Section 2) for the boundary conditions, and reuses the
   `tfwz`/`tftxx`/`tftxy`/`tftyy` columns from the input CSV as the source
   terms at every step.
3. Repeats `n_steps` times the Etapa 10 sequence: explicit Euler update of
   the interior points, boundary-condition re-imposition, dense Gaussian
   elimination Poisson re-solve for `psi`, and recomputation of `u`/`v` from
   the updated `psi`.
4. Writes an output CSV with columns `x,y,wz,txx,txy,tyy,psi,u,v` (values
   after `n_steps` steps, full grid).

Both the Python implementation and the Fortran reference use the same
second-order finite-difference operators, the same `wz`-boundary
simplification, and exact solves of the same discrete Poisson system as
Etapa 10 -- see
[`docs/case-12-time-marching-comparison.md`](case-12-time-marching-comparison.md)
Sections 2-3 for the full discussion. See
[`validation/fortran_reference/case12_multistep/README.md`](../validation/fortran_reference/case12_multistep/README.md)
for compile and run instructions.

## 4. Observed results

`compare_case12_multistep_reference` compares each of `wz`, `Txx`, `Txy`,
`Tyy`, `psi`, `u`, `v` after `n_steps = 10` time-marching steps
(`dt = 1.0e-5`, `9 x 9` grid) between Python and the Fortran reference:

```text
  wz: max_abs_error=4.440892e-16 max_rel_error=2.220446e-16 passed=True
 txx: max_abs_error=4.440892e-16 max_rel_error=2.387118e-16 passed=True
 txy: max_abs_error=4.440892e-16 max_rel_error=2.220389e-16 passed=True
 tyy: max_abs_error=4.440892e-16 max_rel_error=2.220303e-16 passed=True
 psi: max_abs_error=5.551115e-17 max_rel_error=5.551115e-17 passed=True
   u: max_abs_error=3.330669e-16 max_rel_error=3.330669e-16 passed=True
   v: max_abs_error=2.220446e-16 max_rel_error=2.220446e-16 passed=True
```

All seven components agree to within machine precision (`~4.4e-16`), as
expected since both implementations apply the same per-step formulas
`n_steps` times. [`tests/test_case12_multistep_march.py`](../tests/test_case12_multistep_march.py)
asserts `max_abs_error < 1e-12` and `max_rel_error < 1e-12` for all seven
components.
