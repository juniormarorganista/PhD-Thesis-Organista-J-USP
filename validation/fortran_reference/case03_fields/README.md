# Case 03 fields and source terms Fortran reference

This directory contains a standalone Fortran program that exports reference
values for the MMS Case 03 exact fields and source terms:

```text
u, v, wz, psi, txx, txy, tyy, tfwz, tfTxx, tfTxy, tfTyy
```

The expressions mirror the original routines:

```text
src/fortran_original/4Order_LPOG_Euler/case_03.f::exact_solutions_case_03(t)
src/fortran_original/4Order_LPOG_Euler/case_03.f::source_term_case_03(t)
```

`boundaries_condictions_case_03` is not separately exported, for the same
reason as Case 01 (see `validation/fortran_reference/case01_fields/README.md`).

`u`, `v`, `wz`, `psi` are algebraically identical to Cases 01 and 02. The
polymeric stress field uses the same trigonometric ansatz as Case 12
(`(1 - beta) * (a1 + a3 cos(pi x) + a2 sin(pi x)) * (b1 + b3 cos(pi y) + b2
sin(pi y))`), unlike Case 01's spatially uniform stress or Case 02's
quadratic-polynomial stress.

Default parameters (`Rey=1`, `Wi=1`, `beta=0.5`, `epsilon=0`, `xi=0`,
`alphaG=0`, `at=0`, all trigonometric `a`/`b` coefficients `=1`) match
`Case03Parameters`/`Case03SourceTermParameters` in the Python port.

The original Fortran thesis code is not modified.

## Transcription method

Given the density of `case_03.f`'s source terms (up to 225 parenthesis
pairs in a single expression), both this reference file and the Python
port (`source_terms/case_03.py`) were generated by mechanical scripts
rather than retyped by hand:

1. A Fortran-to-Fortran script strips the Fortran77 fixed-form
   continuation prefix and renames legacy/generic intrinsics
   (`dcos`/`Sin`/`dexp` -> `cos`/`sin`/`exp`), preserving every
   parenthesis of the original character-for-character. Used to build
   this `.f90` file.
2. A Fortran-to-Python script performs the same continuation-stripping
   and intrinsic renaming (-> `np.cos`/`np.sin`/`np.exp`, `pii` ->
   `np.pi`), then splits the result into its top-level additive terms.
   Used to build `source_terms/case_03.py`'s `term_1`, `term_2`, ...
   variables, copied verbatim rather than retyped.

Both files were therefore derived independently from the same original
text by two different (but equally mechanical) transformations, and then
cross-validated numerically -- the strongest practical guarantee against
a silent transcription error, since the two paths would have to share the
same mistake to both agree and both be wrong.

## Compile

```powershell
gfortran -O2 -std=f2008 `
  validation\fortran_reference\case03_fields\case03_fields_reference.f90 `
  -o validation\fortran_reference\case03_fields\case03_fields_reference.exe
```

## Generate reference CSV

```powershell
.\validation\fortran_reference\case03_fields\case03_fields_reference.exe `
  validation\reference_data\case03_fields_5x5_default.csv 5 5

.\validation\fortran_reference\case03_fields\case03_fields_reference.exe `
  validation\reference_data\case03_fields_9x9_default.csv 9 9
```
