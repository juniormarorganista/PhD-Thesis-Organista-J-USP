# Case 11 fields and source terms Fortran reference

This directory contains a standalone Fortran program that exports reference
values for the MMS Case 11 exact fields and source terms:

```text
u, v, wz, psi, txx, txy, tyy, tfwz, tfTxx, tfTxy, tfTyy
```

The expressions mirror the original routines:

```text
src/fortran_original/4Order_LPOG_Euler/case_11.f::exact_solutions_case_11(t)
src/fortran_original/4Order_LPOG_Euler/case_11.f::source_term_case_11(t)
```

`boundaries_condictions_case_11` is not separately exported, for the same
reason as Case 01 (see `validation/fortran_reference/case01_fields/README.md`).

`u`, `v`, `wz`, `psi` are algebraically identical to Case 10 (and Case
12). The polymeric stress field is a quadratic polynomial in `x` and
`y`, the same ansatz as Case 02.

Default parameters (`Rey=1`, `Wi=1`, `beta=0.5`, `epsilon=0`, `xi=0`,
`alphaG=0`, `at=0`, all `a`/`b` coefficients `=1`) match
`Case11Parameters`/`Case11SourceTermParameters` in the Python port.

The original Fortran thesis code is not modified.

## Transcription method

Generated by the established mechanical scripts; every term was copied
verbatim into both this reference and `source_terms/case_11.py` (`tfTxx`
and `tfTyy` are the densest, each with around 177-179 matched
parenthesis pairs). The Python module was assembled programmatically
and normalized by `ruff format`. Both transcriptions agreed at machine
precision on the first attempt.

## Compile

```powershell
gfortran -O2 -std=f2008 `
  validation\fortran_reference\case11_fields\case11_fields_reference.f90 `
  -o validation\fortran_reference\case11_fields\case11_fields_reference.exe
```

## Generate reference CSV

```powershell
.\validation\fortran_reference\case11_fields\case11_fields_reference.exe `
  validation\reference_data\case11_fields_5x5_default.csv 5 5

.\validation\fortran_reference\case11_fields\case11_fields_reference.exe `
  validation\reference_data\case11_fields_9x9_default.csv 9 9
```
